# Contributing to Attendance Hub

Thank you for your interest in contributing to Attendance Hub! We appreciate your help in making this project better.

## Code of Conduct

By participating in this project, you agree to abide by our Code of Conduct. Please be respectful and professional in all interactions.

## How to Contribute

### 1. Report Bugs
If you find a bug, please open an issue on GitHub. Include as much detail as possible, such as:
- Steps to reproduce the bug
- Expected behavior
- Actual behavior
- Screenshots (if applicable)

### 2. Suggest Features
We welcome new ideas! If you have a feature suggestion, please open an issue and describe:
- The problem you want to solve
- The proposed solution
- Any alternatives you've considered

### 3. Submit Pull Requests
To submit a pull request:
1. Fork the repository.
2. Create a new branch for your changes (`git checkout -b feature/your-feature-name`).
3. Make your changes and ensure they follow our coding standards.
4. Run tests and linting to verify your changes.
5. Commit your changes with clear and descriptive messages.
6. Push your branch to your fork (`git push origin feature/your-feature-name`).
7. Open a pull request against the `main` branch of the original repository.

## Development Setup

1. **Install dependencies**:
   ```bash
   npm install
   ```

2. **Run the development server**:
   ```bash
   npm run dev
   ```

3. **Linting**:
   Ensure your code follows the project's styling conventions. We use ESLint and Prettier for code formatting.

## Coding Standards

- Use functional components and hooks for React.
- Follow the existing folder structure.
- Use Tailwind CSS for styling.
- Write clear and concise commit messages.
- Ensure all new features are documented in the README.

## Pull Request Guidelines

- Keep pull requests focused on a single change.
- Provide a clear description of the changes.
- Link any related issues.
- Ensure the build passes and there are no linting errors.

We look forward to your contributions!
